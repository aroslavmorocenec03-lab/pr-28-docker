# Звіт до практичної роботи №28

## Встановлення Docker та розгортання вебсервера

Мета роботи — ознайомитися з образами й контейнерами, виконати базові операції Docker, створити Linux-образ зі статичним сайтом та запустити Nginx із публікацією порту, підключенням папки й перевіркою стану.

## Поточний стан перевірки

Файли проєкту та сценарії підготовлено; синтаксис усіх чотирьох PowerShell-сценаріїв перевірено без помилок. HTML і CSS переглянуто в браузері на окремому локальному сервері без Docker — ця перевірка не зараховується як запуск контейнера. На початку перевірки Docker Desktop і WSL на комп’ютері були відсутні. Установлено WSL 3.0.3.0. Docker Desktop поки не встановлено: його інсталятор повідомив, що компонент Windows VirtualMachinePlatform не активовано, а подальший запит прав адміністратора було скасовано. **Збірка образу, запуск контейнерів та скриншоти Docker ще не підтверджені.** Цей розділ потрібно оновити після фактичного виконання команд.

## Підготовлена конфігурація

| Параметр | Значення |
| --- | --- |
| ОС контейнера | Alpine Linux |
| Вебсервер | Nginx |
| Базовий образ | `nginx:stable-alpine` |
| Власний образ | `my-static-website:latest` |
| Початкова версія | `my-static-website:v1` |
| Контейнер сайту | `static-website` |
| Порт контейнера | 80 |
| Порт комп’ютера | 8080, доступ через localhost |
| Файли сайту в контейнері | `/usr/share/nginx/html` |
| Bind mount у Compose | `./html`, лише читання |
| Перевірка стану | HTTP healthcheck кожні 10 секунд |

## Порядок виконання

1. Перевірити довідку Docker та Compose, виконати `docker run hello-world`.
2. Завантажити BusyBox, переглянути його ID, видалити образ і завантажити повторно.
3. Виконати `echo` в BusyBox, порівняти `docker ps` і `docker ps -a`, запустити наявний контейнер, зупинити й видалити його.
4. Створити образ із початковою сторінкою та запустити його на порту 8080.
5. Перебудувати образ із власною сторінкою версії 2 і перестворити контейнер.
6. Перевірити HTTP 200, стан `healthy`, списки образів і контейнерів, статистику ресурсів.
7. Окремо перевірити Compose з read-only bind mount і зібрати фактичні результати для звіту.

Відповідні команди та сценарії наведено в README. Наведений вище порядок є планом перевірки, а не твердженням про вже виконані запуски.

## Потрібні докази виконання

- Фактичний вивід `docker images` і скриншот списку образів.
- Фактичний вивід `docker ps` та скриншот запущеного контейнера з портом 8080.
- Скриншот сайту, отриманого саме від Nginx у контейнері за адресою `http://localhost:8080`.
- Відповідь HTTP 200 і стан контейнера `healthy`.

Ці докази додаються після запуску Docker. Порожні або згенеровані приклади виводу не використовуються як фактичні результати.

## Відповіді на запитання для самоконтролю

1. **Чим контейнер відрізняється від віртуальної машини?** Віртуальна машина має власну гостьову ОС і ядро. Контейнер ізолює процеси та файлову систему, використовуючи ядро середовища, у якому працює Docker Engine. Linux-контейнери Docker Desktop на Windows запускаються через Linux-середовище, наприклад WSL 2.
2. **Що таке Docker host?** Середовище, у якому працює Docker Engine і запускаються контейнери. На Windows із Linux-контейнерами це Linux-середовище Docker Desktop; клієнт Docker може працювати у Windows.
3. **Як видалити образ, який використовується контейнером?** Спочатку визначити пов’язаний контейнер, зупинити його та видалити, потім виконати `docker image rm <IMAGE_ID>`. Видалення контейнера може втратити дані його writable layer, тому потрібні файли заздалегідь зберігають поза контейнером.
4. **Чим відрізняються image, container і volume?** Image — шаблон із файловою системою та конфігурацією; container — створений на його основі екземпляр із процесом і власним writable layer; volume — окреме сховище даних під керуванням Docker, яке може існувати після видалення контейнера.
5. **Яка команда створює образ із Dockerfile?** `docker build -t my-static-website .` — збирає образ із контексту поточної папки та присвоює йому ім’я.
6. **Яка інструкція запускає програму в контейнері?** У цій роботі — `CMD ["nginx", "-g", "daemon off;"]`. Вона задає команду за замовчуванням при створенні контейнера. Для визначення виконуваного процесу також існує `ENTRYPOINT`; `RUN` виконує команди під час збирання образу.

## Висновок щодо підготовленого проєкту

Підготовлено структуру Docker-проєкту, початкову й оновлену сторінки, публікацію порту, read-only bind mount та healthcheck. Висновок про успішний запуск контейнера можна додати лише після фактичного виконання перевірок і отримання скриншотів.
